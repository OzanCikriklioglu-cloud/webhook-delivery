================================================================
   WEBHOOK DELIVERY - TESTING GUIDE (ELI5 Edition)
================================================================

Think of your system like this:
  - YOU fire an event ("hey, something happened!")
  - Your app puts it in a QUEUE (RabbitMQ - like a mailbox)
  - A WORKER picks it up from the queue and delivers it to a URL
  - Every attempt (success or fail) is LOGGED

Let's test all of that step by step.


================================================================
STEP 0 — BEFORE YOU START
================================================================

1. Make sure Docker Desktop is running on your computer.

2. Open a terminal in your project folder and run:
      docker-compose up --build

   This starts 3 things:
      - Your Spring Boot app     → runs on http://localhost:8080
      - PostgreSQL database      → runs on port 5432
      - RabbitMQ                 → runs on port 5672

   Wait until you see something like:
      "Started WebhookDeliveryApplication in X seconds"

3. Open Postman. We will use it to send requests to the app.

4. Open your browser and go to:
      http://localhost:15672

   This is the RabbitMQ Dashboard (like a control panel).
   Login with:
      Username: user
      Password: pass

   You will use this to SEE messages flowing through the queue.
   Keep this tab open.


================================================================
STEP 1 — REGISTER A USER
================================================================

In Postman:

   Method:  POST
   URL:     http://localhost:8080/api/auth/register

   Click "Body" → select "raw" → select "JSON" from the dropdown

   Paste this:
   {
     "email": "test@example.com",
     "password": "password123"
   }

   Click Send.

   You should get back:
   {
     "token": "eyJhbGciOiJIUzI1NiJ9...(long string)"
   }

   COPY THAT TOKEN. You will need it for every request after this.

   WHY: Every API call requires you to prove who you are.
        The token is your identity badge.


================================================================
STEP 2 — LOGIN (GET YOUR TOKEN)
================================================================

   Method:  POST
   URL:     http://localhost:8080/api/auth/login
   Body (JSON):
   {
     "email": "test@example.com",
     "password": "password123"
   }

   You get back the same token format. Copy it.

   HOW TO USE THE TOKEN IN POSTMAN:
   - Click the "Authorization" tab in Postman
   - Type: Bearer Token
   - Paste your token in the "Token" field
   - Do this for every request below


================================================================
STEP 3 — GET A FREE TEST URL (pipedream.com)
================================================================

   Go to https://pipedream.com/requestbin in your browser.

   Click the "Create a RequestBin" button.

   You will see a unique URL like:
      https://enyvz5pjsejyaum.m.pipedream.net

   Copy that URL.

   WHY: Your app needs a real URL to deliver webhooks to.
        RequestBin shows you every request it receives live.
        Think of it as a test inbox that shows what your app sent.

   Keep this tab open too.


================================================================
STEP 4 — CREATE AN ENDPOINT
================================================================

   An "endpoint" is a registered target URL in your system.
   You are telling your app: "when events happen, send them HERE".

   Method:  POST
   URL:     http://localhost:8080/api/endpoints
   Auth:    Bearer Token (paste your token)
   Body (JSON):
   {
     "name": "My Test Endpoint",
     "url": "https://YOUR-UNIQUE-URL-HERE.m.pipedream.net"
   }

   Replace the URL with what you copied from pipedream.com/requestbin.

   You should get back something like:
   {
     "id": 1,
     "name": "My Test Endpoint",
     "url": "https://....m.pipedream.net",
     "active": true,
     ...
   }

   NOTE DOWN THE "id" VALUE (e.g. 1). You need it in the next step.


================================================================
STEP 5 — FIRE AN EVENT (THE MAIN TEST!)
================================================================

   This is the big one. Firing an event does ALL of this:
      1. Saves the event to the database
      2. Puts it in the RabbitMQ queue
      3. Worker picks it up
      4. Worker makes HTTP POST to your pipedream.com URL
      5. Logs the result

   Method:  POST
   URL:     http://localhost:8080/api/events
   Auth:    Bearer Token
   Body (JSON):
   {
     "endpointId": 1,
     "eventType": "payment.completed",
     "payload": "{\"orderId\": \"ORD-001\", \"amount\": 99.99}"
   }

   Replace "endpointId" with the id you got in Step 4.

   You should get back:
   {
     "id": 1,
     "eventId": "some-uuid-here",
     "eventStatus": "CREATED",
     "deliveryStatus": "PENDING",
     ...
   }

   NOW — within 1-2 seconds — go check:
      a) pipedream.com tab → you should see a new request arrive!
      b) RabbitMQ dashboard → http://localhost:15672


================================================================
STEP 6 — HOW TO USE THE RABBITMQ DASHBOARD
================================================================

   Go to http://localhost:15672
   Login: user / pass

   Click on "Queues and Streams" tab at the top.

   You will see 3 queues:
      - webhook.delivery.queue   ← events waiting to be delivered
      - webhook.retry.queue      ← failed events waiting to retry
      - webhook.dlq.queue        ← events that failed all retries (dead)

   WHAT TO LOOK FOR:

   When you fire an event:
      - "webhook.delivery.queue" briefly shows 1 message
      - It disappears almost instantly (worker consumed it)
      - This means: message was received and processed!

   If delivery succeeds:
      - Queue goes back to 0
      - pipedream.com shows the request

   If delivery fails:
      - Message moves to "webhook.retry.queue"
      - After 1 minute it moves back to delivery queue for retry
      - After 3 retries it moves to "webhook.dlq.queue"

   The numbers you see:
      "Ready"     = messages waiting to be picked up
      "Unacked"   = messages being processed right now
      "Total"     = Ready + Unacked


================================================================
STEP 7 — CHECK DELIVERY LOGS
================================================================

   Your app logs every delivery attempt. Let's check them.

   Method:  GET
   URL:     http://localhost:8080/api/events/1/logs
   Auth:    Bearer Token

   (Replace "1" with your event id from Step 5)

   You should see something like:
   [
     {
       "id": 1,
       "attemptNumber": 1,
       "status": "DELIVERED",
       "httpStatusCode": 200,
       "durationMs": 342,
       ...
     }
   ]

   status: "DELIVERED" means it worked!
   status: "RETRYING"  means it failed and will retry
   status: "FAILED"    means all retries exhausted


================================================================
STEP 8 — CHECK EVENT STATUS
================================================================

   Method:  GET
   URL:     http://localhost:8080/api/events/1
   Auth:    Bearer Token

   After successful delivery you should see:
   {
     "eventStatus": "COMPLETED",
     "deliveryStatus": "DELIVERED",
     "retryCount": 0,
     ...
   }


================================================================
STEP 9 — TEST FAILURE + RETRY (Optional but cool)
================================================================

   What if the target URL is down or returns an error?
   Let's simulate that.

   1. Create a NEW endpoint with a bad URL:
      Method:  POST
      URL:     http://localhost:8080/api/endpoints
      Auth:    Bearer Token
      Body:
      {
        "name": "Bad Endpoint",
        "url": "http://localhost:9999/nonexistent"
      }

      Note the new id (e.g. 2)

   2. Fire an event to that bad endpoint:
      Method:  POST
      URL:     http://localhost:8080/api/events
      Auth:    Bearer Token
      Body:
      {
        "endpointId": 2,
        "eventType": "test.failure",
        "payload": "{\"test\": true}"
      }

   3. Check the delivery logs:
      GET http://localhost:8080/api/events/2/logs

      You should see status: "RETRYING"
      retryCount will increase each attempt.

   4. In RabbitMQ dashboard, watch "webhook.retry.queue"
      You should see 1 message sitting there waiting.
      After 1 minute it moves back to delivery queue and tries again.
      After 3 total attempts it goes to "webhook.dlq.queue".


================================================================
STEP 10 — RETRY A FAILED EVENT MANUALLY
================================================================

   If an event has status "FAILED" you can retry it manually:

   Method:  POST
   URL:     http://localhost:8080/api/events/1/retry
   Auth:    Bearer Token
   Body:    (leave empty or send {})

   This resets retryCount to 0 and re-queues it immediately.


================================================================
QUICK REFERENCE — ALL API ENDPOINTS
================================================================

AUTH:
   POST   /api/auth/register          → create account
   POST   /api/auth/login             → get token

ENDPOINTS:
   POST   /api/endpoints              → register a target URL
   GET    /api/endpoints              → list your endpoints
   GET    /api/endpoints/{id}         → get one endpoint
   PUT    /api/endpoints/{id}         → update endpoint
   DELETE /api/endpoints/{id}         → delete endpoint

EVENTS:
   POST   /api/events                 → fire an event
   GET    /api/events                 → list all your events
   GET    /api/events/{id}            → get one event
   GET    /api/events/{id}/logs       → see delivery attempts
   POST   /api/events/{id}/retry      → retry a failed event
   POST   /api/events/{id}/cancel     → cancel an event
   GET    /api/events/statistics      → see counts (total/done/failed)
   GET    /api/events/endpoint/{id}   → events for one endpoint


================================================================
WHAT SUCCESS LOOKS LIKE (SUMMARY)
================================================================

   After firing an event to a valid URL:

   pipedream.com        → shows the incoming POST request with your payload
   RabbitMQ dashboard   → delivery queue briefly hits 1, then drops to 0
   GET /events/{id}     → eventStatus: "COMPLETED", deliveryStatus: "DELIVERED"
   GET /events/{id}/logs → shows 1 log entry, status: "DELIVERED", httpStatusCode: 200

   If all 4 of those are true → Day 5 is working perfectly.


================================================================
TROUBLESHOOTING
================================================================

Problem: App won't start
   → Make sure Docker Desktop is running
   → Run: docker-compose down -v  then  docker-compose up --build

Problem: 401 Unauthorized
   → Your token expired or is wrong
   → Login again, copy the NEW token, update it in Postman

Problem: "Endpoint not found"
   → The endpointId in your event request doesn't match
   → Do GET /api/endpoints to see your endpoint IDs

Problem: pipedream.com never receives anything
   → Check GET /events/{id}/logs to see the error message
   → Check RabbitMQ dashboard → is the message stuck in retry queue?

Problem: RabbitMQ dashboard won't open
   → Go to http://localhost:15672 (not 5672, that's a different port)
   → Make sure Docker containers are running: docker ps
